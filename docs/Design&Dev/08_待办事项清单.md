## 二、待办事项详细说明

### TODO-001　移动端原生 App（根治移动端通话）

- **类型**：功能增强 / 架构决策
- **优先级**：P1（高）—— 影响移动端音视频通话的核心可用性
- **状态**：待评估
- **背景与影响**：
  手机浏览器在**锁屏 / 切后台 / 屏幕熄灭**时，系统为省电会**冻结网页的 JavaScript**，导致 converse 的 BOSH 长轮询连接被掐断。由此产生两类故障：
  1. **收不到来电**（BUG-038）：对方发来的呼叫 IQ 落在已死的会话上，手机端无提示；
  2. **呼不出**：本端发起呼叫时连接已假死，initiate 发不出去。
  网页版只能在「**前台 + 屏幕常亮**」时保持稳定，**无法根治**。
- **建议方案**：手机端做成**原生 App**（系统推送唤醒，锁屏也能弹来电）。可选技术路线：uni-app / React Native 复用现有 Vue3 前端逻辑，或原生重写通话模块。需评估工作量与复用可行性。
- **责任方**：待定（项目负责人拍板技术路线）
- **期望完成**：待评估

### TODO-002　Openfire 4.9.2 BOSH 连接管理 bug 根治 ✅

- **类型**：技术债务
- **优先级**：P2（中）
- **状态**：✅ **已完成（2026-09-21 升级 Openfire 5.1.2）**
- **背景与影响**：
  Openfire 4.9.2 的 BOSH 僵尸会话 bug（重连旧会话不清理、会话 isInitialized=false、complete 事件未消费）导致：离线消息静默丢失（BUG-033）、converse 登录一直重试（BUG-036）、**双向音视频呼叫收不到邀请**（BUG-042）。属 Openfire 上游 bug。
- **解决方案**：升级 Openfire 4.9.2 → **5.1.2**（自建镜像 `openfire-openfire:5.1.2`，base `eclipse-temurin:17-jre` + 官方 tar.gz）。schema 34→38 自动迁移，账号/roster/配置全保留。升级后「同 resource 重新绑定 = 新会话替换旧会话」，配合前端「全局固定 resource `web`」根治僵尸会话累积。数据库备份 `/tmp/openfire_backup_*.sql`、conf 卷备份 `/tmp/of_backup/`，旧镜像 `openfire-openfire:latest`（4.9.2）保留可回滚。
- **责任方**：Openfire 开发 / 运维
- **期望完成**：已完成

### TODO-003　局域网数据库端口收敛

- **类型**：安全加固
- **优先级**：P2（中）—— 开发环境可接受，生产上线前必须完成
- **状态**：待处理
- **背景与影响**：
  主库（5432）与 openfire 独立库（25432）当前在**局域网内可见**，存在被内网端口探测 / 弱口令爆破的风险。

- **责任方**：部署 / 运维
- **期望完成**：生产上线前

### TODO-004　BUG-035 `/sessions` 返回 500 修复

- **类型**：缺陷修复
- **优先级**：P2（中）—— 可选端点，已有管理台会话页规避
- **状态**：✅ 已完成
- **背景与影响**：
  REST API 插件 1.11.0 引用了 `STATUS_CLOSED` 字段，Openfire 4.9.2 无此字段 → `NoSuchFieldError` → `GET /sessions` 返回 500。
- **建议方案**：升级 / 降级 REST API 插件至与 4.9.2 兼容的版本，或继续用管理台会话页查询。
- **责任方**：Openfire 开发
- **期望完成**：✅ 已完成（2026-09-21）—— 随 Openfire 5.1.2 升级 REST API 至 1.12.0，`/sessions` 实测 HTTP 200 正确返回会话列表（含 sessionId/username/sessionStatus/presenceStatus）
