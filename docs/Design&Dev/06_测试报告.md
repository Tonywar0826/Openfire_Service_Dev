## 4. 缺陷详细分析

### BUG-1（P0）：离线消息丢失 — 假死会话

**现象**：yuzhouxiang 发消息给 admin（admin 离线），消息既不投递也不存 ofOffline，admin 上线后收不到。

**根因链**：
1. admin 存在一个**假死的 BOSH 会话**（`isInitialized=false`，SASL 未初始化，`lastActivity=2026-09-20T06:15`，已挂 6+ 小时）
2. 该会话的 `inactivityTimeout=PT30M`（30 分钟），但 **Openfire 未正确清理**这个超时会话
3. yuzhouxiang 发消息给 admin 时，Openfire 认为 admin「在线」（假死会话还在），把消息路由到该会话
4. 路由到假死会话报 `IllegalStateException: A SaslServer instance was not initialized and/or stored on the session`（`SessionPacketRouter.route`）
5. 消息路由失败后**未 fallback 到 ofOffline 离线存储**，静默丢失

**影响**：任何存在假死会话的用户，离线期间收不到消息（消息静默丢失）。

**修复方向**（待定，需进一步确认）：
- 短期：管理台/脚本踢掉假死会话（`SessionManager.closeSession`）
- 根治：Openfire 侧修复假死会话清理逻辑；或前端 converse 确保会话正常关闭/重连

### BUG-2（P1）：改资料不同步

**现象**：平台 `PUT /users/{id}` 改 real_name/email 后，ofUser 的 name/email 未更新。

**根因**：`backend/app/services/user_service.py` 的 `update_user` 只更新本地 postgres，未调用 `im_service.sync_user_to_openfire`（而 `create_user`/`reset_password` 都调了）。

**修复方向**：`update_user` 增加调用 `sync_user_to_openfire(user, password)`，其中 password 从 Redis 缓存 `im_pwd:<username>` 取回（无缓存则跳过，仅同步 name/email）。

### BUG-3（P2）：REST API /sessions 500

**现象**：`GET /plugins/restapi/v1/sessions` 返回 500。

**根因**：REST API 插件 1.11.0 的 `SessionController.getAllSessions` 引用 `STATUS_CLOSED` 字段，Openfire 4.9.2 该字段已改名/移除，报 `NoSuchFieldError`。属插件与服务器版本兼容性问题。

**影响**：`/sessions` 是可选端点（在线会话查询），不影响账号同步核心。在线会话可改用管理台「会话」页或数据库 `ofPresence`/内存查询。

1. **核心 IM 能力正常**：账号同步、登录认证、通讯录、群聊、账号生命周期（离职断 IM）全部通过。
2. **1 个 P0 阻塞项**（BUG-1 离线消息丢失）需优先修复，根因是 Openfire 假死会话未被清理。
3. **1 个 P1**（BUG-2 改资料不同步）修复简单，建议一并处理。
4. **1 个 P2**（BUG-3 /sessions 500）属插件兼容性问题，可选端点，可延后。
5. 音视频（F-09）、附件（F-10）需浏览器人工测试，未纳入本次自动化范围。
