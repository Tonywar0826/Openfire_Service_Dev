## 一、P0 目标（一句话）

把「现在手工搭的 Openfire 部署」升级成「参数化 + 图形化管理台 + 一键部署/备份/恢复 + 监控看板」，**不动现有运行中的 Openfire**，风险最低。

## 二、P0 范围边界

**做（范围内）**：
- 参数化 docker-compose（.env 驱动，内存/CPU 资源参数化，为 P1 垂直扩展打基础）
- 部署管理平台后端（部署/备份/恢复/状态 4 类 API + 目标服务器管理）
- **目标服务器管理**：添加客户服务器，支持三种连接方式（Agent / SSH / Docker 远程端口，可插拔），实施人员按客户情况选择
- 部署管理平台前端（概览 + 部署向导 + 备份管理 + 监控看板 4 个页面）
- **部署向导支持「自定义」模式**：自由指定服务数量（Openfire N 个 / coturn N 个 / 数据库方案自选），部署工具按数量动态生成 compose
- 复用现有 Prometheus + Grafana 监控

**不做（范围外，留给 P1/P2/P3）**：
- ❌ 垂直扩展（改内存/CPU + 重启）→ P1（与水平扩展一起，作为「一键扩展」的两种方式）
- ❌ 一键扩展（加实例）→ P1
- ❌ 一键回退（版本快照）→ P1
- ❌ Hazelcast 集群 / sticky 负载均衡 → P2
- ❌ Patroni 全自动高可用 → P2
- ❌ 跨机房 / 异地备份 → P3

## 三、任务分解（WBS）

### 任务 1：参数化 docker-compose

| 子任务 | 做什么 | 交付物 | 验收标准 |
|--------|--------|--------|---------|
| 1.1 提取参数 | 把镜像/内存/端口/密码/域名抽到 `.env` | `deploy/.env` 模板 | 所有可配置项都在 .env，有注释 |
| 1.2 改造 compose | `docker-compose.yml` 引用 .env 变量 | 改造后的 compose | `docker compose config` 校验通过 |
| 1.3 等价验证 | 用参数化版本部署，结果和现有一致 | 验证记录 | 部署后 Openfire 正常登录、消息正常 |

### 任务 2：管理平台后端（FastAPI，独立容器）

| 子任务 | 做什么 | 交付物 | 验收标准 |
|--------|--------|--------|---------|
| 2.1 项目骨架 | 后端工程 + 配置 + 健康检查 | 后端骨架 | `/health` 返回 200 |
| 2.2 部署 API | 后端调用 docker compose 一键部署/停止 | `POST /api/deploy` | 界面点「部署」→ 实际拉起 Openfire |
| 2.3 备份 API | 后端调用 pg_dump + 卷备份 | `POST /api/backup` | 点「备份」→ 生成备份文件（DB+配置+卷） |
| 2.4 恢复 API | 从备份一键恢复 | `POST /api/restore` | 点「恢复」→ 数据还原、服务重启 |
| 2.5 状态 API | 查实例数/健康/资源 | `GET /api/status` | 返回实例状态、CPU/内存、在线数 |
| 2.6 目标服务器管理 | 添加/编辑客户服务器 + 三种连接器 | `POST /api/targets` + Connector 抽象 | 选连接方式后能连通、能查状态 |
| 2.7 配置同步 | 部署后同步 Openfire 参数 ↔ 协作平台 .env/nginx，逐项校验 | `config_sync.py` | 10 项配置逐项校验，每项返回「名称+概要说明+方向+状态」 |
| 2.8 自检校验 | 部署后从容器→服务→功能→Bug 回归逐项检查 | `selfcheck.py` | 4 层检查项逐项执行返回状态，46 Bug 全部映射 |

### 任务 3：管理平台前端（Vue3）

| 子任务 | 做什么 | 交付物 | 验收标准 |
|--------|--------|--------|---------|
| 3.1 界面骨架 | 三栏布局 + 左侧导航 + 顶部栏 | 布局骨架 | 按 01 原型布局，7 菜单可点 |
| 3.2 概览页 | 状态卡 + 拓扑图 + 告警列表 | 概览页 | 数据来自后端 status API |
| 3.3 部署向导页 | 选规模（三档+**自定义**）→ 填参数 → 一键部署 | 部署页 | 按 01 原型 4 步向导；自定义模式可指定服务数量 |
| 3.4 部署结果页 | 部署后展示「配置同步清单 + 自检清单」逐项状态 | 结果页 | 配置同步 10 项 + 自检 4 层逐项状态灯 + 汇总 |
| 3.5 备份管理页 | 备份列表 + 立即备份 + 恢复 | 备份页 | 点「立即备份」触发后端，列表刷新 |
| 3.6 监控看板页 | 集成现有 Grafana 或指标 | 监控页 | 能看到资源/业务指标 |

### 任务 4：监控（部署到目标服务器，部署平台只读展示）

| 子任务 | 做什么 | 交付物 | 验收标准 |
|--------|--------|--------|---------|
| 4.1 监控栈随部署 | 部署 Openfire 时，Prometheus + Grafana + exporters 一起部署到目标服务器容器内 | 目标服务器监控栈 | 目标服务器上监控栈跑起来 |
| 4.2 只读展示 | 部署平台「监控看板」页读目标服务器监控数据展示 | 监控看板页 | 看板显示目标服务器的实例/资源指标 |

### 任务 5：容器化部署 + 端到端验证

| 子任务 | 做什么 | 交付物 | 验收标准 |
|--------|--------|--------|---------|
| 5.1 管理平台容器化 | 管理台作为独立容器跑进协作平台 compose | 管理台容器 | 独立容器，随协作平台起停 |
| 5.2 端到端验证 | 部署→备份→恢复→监控 全链路 | 测试报告 | 四条链路全通，见「六、P0 验收标准」 |

## 四、技术选型（P0 沿用协作平台既有栈）

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 | FastAPI + Python | 协作平台已有，复用 |
| 前端 | Vue3 + Vite + TS | 协作平台已有，复用 |
| 部署执行 | Docker + docker compose | 底座不变 |
| 远程连接 | SSH / Docker TLS / Agent 三种可插拔 | 实施人员按客户情况选择 |
| 监控 | Prometheus + Grafana | 随 Openfire 部署到目标服务器；部署平台只读展示 |
| 备份 | pg_dump + tar（卷） | 简单可靠，P0 够用 |

## 六、P0 整体验收标准（用户确认依据）

| 验收项 | 通过标准 |
|--------|---------|
| 远程部署 | 添加目标服务器（任选连接方式）→ 远程部署 Openfire 成功 |
| 零代码 | 全程界面点击完成，无命令行/脚本输入 |
| 一键部署 | 界面点「部署」→ Openfire 从零跑起来 |
| 一键备份 | 界面点「备份」→ 生成完整备份（DB+配置+卷） |
| 一键恢复 | 界面点「恢复」→ 数据还原、服务正常 |
| 配置同步 | 部署后 10 项配置逐项校验，显示「配置名称 + 概要说明 + 状态」 |
| 自检清单 | 部署后 4 层（容器→服务→功能→Bug 回归）逐项状态，46 Bug 全部映射 |
| 监控可见 | 界面能看到 Openfire/DB 状态和资源指标 |
| 不破坏现状 | 现有运行中的 Openfire 不受影响 |

## 七、风险与依赖

| 风险/依赖 | 说明 | 应对 |
|----------|------|------|
| 远程连接客户服务器的权限 | 实施人员远程操作客户 Docker | 三种连接器可插拔：Agent（推荐）/SSH/Docker 端口；默认 Agent 权限最小 |
| 备份大文件 | fileupload 卷可能较大 | P0 用 tar，大文件留 P1 优化 |
| 现有环境不中断 | 参数化后部署不能影响运行中的 Openfire | 1.3 等价验证先行 |
