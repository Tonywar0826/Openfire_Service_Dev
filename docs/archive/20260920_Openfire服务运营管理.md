### 2.1 监控体系总览

```
┌─────────────────────────────────────────────────────────────┐
│                        Grafana 可视化看板                      │

                               │
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
   Prometheus            Elasticsearch          Alertmanager
   （指标时序库）           + Kibana              （告警路由）
        │                （日志检索）                 │
        │                      │                      │
   ┌────┴─────┐          fluent-bit          钉钉/邮件/IM系统消息
   │ exporter │         （日志采集）                 │
   └────┬─────┘                │                      │
        │                      │                      │
┌───────┴──────────────────────┴──────────────────────┴───────┐
│  被监控对象：10 容器（Openfire / openfire-db / postgres /       │
│  redis / rabbitmq / minio / coturn / backend / web）          │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 监控分层（自下而上定位）

| 层 | 监控对象 | 手段 |
|---|---|---|
| L1 容器 | 所有容器 CPU/内存/磁盘/网络 | cadvisor + node_exporter |
| L2 应用 | Openfire JVM（堆/GC/线程）、backend | jmx_exporter |
| L3 协议 | c2s/BOSH/WS 连接、在线会话、SASL 认证 | JMX / 日志统计 |
| L4 依赖 | postgres/redis/rabbitmq/minio/coturn | 各自 exporter |
| L5 端到端 | IM 全链路（登录→发消息） | BOSH 探针脚本 |

## 三、详细监控指标

### 3.1 容器性能指标（cadvisor）

| 指标 | Prometheus 指标名 | 告警阈值（建议） |
|---|---|---|
| CPU 使用率 | `container_cpu_usage_seconds_total` | 持续 >80% P2 |
| 内存使用 | `container_memory_usage_bytes` / `_working_set_bytes` | >容器 limit 85% P1 |
| 磁盘读/写 | `container_fs_reads_bytes_total` / `_writes_bytes_total` | 持续高 P2 |
| 网络收/发 | `container_network_receive_bytes_total` / `_transmit_bytes_total` | 突增 P2 |
| 磁盘空间（宿主机） | `node_filesystem_avail_bytes` | 剩余 <20% P1（尤其 WAL 归档 /backups） |

**重点监控对象**：`collab-openfire`（内存 1g limit）、`collab-openfire-db`（512m limit）、`collab-postgres`（1g limit）、`collab-coturn`（256m）。

### 3.2 Openfire 组件指标（JMX + 日志 + 数据库）

| 类别 | 指标 | 采集方式 | 阈值 |
|---|---|---|---|
| **JVM** | 堆内存 used/max | jmx_exporter `jvm_memory_used_bytes` | 堆 >85% P2 |
| | GC 次数/耗时 | `jvm_gc_pause_seconds` | GC 频繁 P2 |
| | 线程数 / 死锁 | `jvm_threads_*` | 线程泄漏 P2 |
| | DB 连接池使用率 | JMX | >90% P1 |
| **连接** | c2s 连接数 | JMX / 管理台 Session Summary | 异常波动 P2 |
| | BOSH 会话数 | JMX / 日志 | 异常波动 P2 |
| | WebSocket 会话数 | JMX | 异常波动 P2 |
| | 在线会话数 | `GET /sessions`（REST API）或管理台「会话」页 | 5min 突降 >50% P1 |
| | 空闲会话（Closing idle） | 日志计数 | 激增 P2 |
| **认证** | SASL 成功率/失败率 | 日志 `grep SASLAuthentication` | 失败率 >10%/5min P1 |
| | 失败原因分布 | 日志 | not-authorized 频发 = 暴力破解 P1 |
| **消息** | 消息吞吐 msg/min | JMX / Monitoring 插件 | 归零 P2 |
| | 离线消息量 | `ofOffline` 行数 | 积压增长 P2 |

### 3.3 依赖组件指标

| 组件 | 指标 | exporter | 阈值 |
|---|---|---|---|
| **postgres** | 连接数、慢查询、缓存命中 | postgres_exporter | 连接耗尽 P1、慢查 >1s P2 |
| | 表大小增长（ofMessageArchive/ofMucRoom） | 定时 SQL | 逼近磁盘 P2 |
| **redis** | 内存 used/max、命中率、连接数 | redis_exporter | 内存 >80% P1 |
| **rabbitmq** | 队列深度、积压、消费速率 | rabbitmq Prometheus 插件 | 积压 >阈值 P1 |
| **minio** | 存储用量、健康、请求延迟 | minio 自带 /minio/v2/metrics | 健康失败 P0 |
| **coturn** | 活跃中继数、带宽 | coturn 日志 / 端口流量 | 中继耗尽 P2 |
| **backend** | 请求延迟、错误率、影子账号同步成功率 | 后端日志 + /metrics | 同步失败持续 P1 |

### 3.4 端到端探针（黑盒）

| 探针 | 方法 | 指标 | 阈值 |
|---|---|---|---|
| IM 登录探针 | cron 跑 `test-bosh-login.py`（登录→发消息→登出） | `im_login_success` / `im_login_latency_ms` | 连续 2 次失败 P0 |

## 四、Openfire 后台数据查看与查询（重点）

> 结论：Openfire 的**全部后台数据都在独立库 `openfire` 里（33 张表）**，可通过「管理控制台（界面）+ 数据库（SQL）+ 日志 + REST API」四种方式查看。下面给出完整方法。

### 4.1 管理控制台（界面化查看）

浏览器 `http://localhost:19090`，admin 登录，左侧菜单：

| 菜单 | 能看/能管 |
|---|---|
| 服务器 → 服务器设置 | 域名、端口、资源策略 |
| 服务器 → 系统属性 | 全部 `ofProperty` 配置 |
| 服务器 → 缓存摘要 | 缓存命中率 |
| 用户/群组 | 用户增删改查、群组管理 |
| 会话 | 在线会话列表、踢人下线 |
| 分组聊天 | 群聊房间（MUC）管理 |
| 插件 | 已装插件、上传插件 |
| 统计 | 需装 Monitoring 插件（聊天统计/消息归档） |

### 4.2 数据库直查（最全，33 张表）

连接：`docker exec collab-openfire-db psql -U openfire -d openfire`

**表分类全景**：

| 分类 | 表 | 存什么 |
|---|---|---|
| **用户** | `ofUser` | 用户账号（username/name/email/password） |
| | `ofUserProp` | 用户扩展属性 |
| | `ofUserFlag` | 用户标记 |
| | `ofVCard` | 用户名片（头像/电话等） |
| | `ofPrivateList` | 隐私列表 |
| **通讯录** | `ofRoster` | 好友关系（sub 订阅） |
| | `ofRosterGroups` | 好友分组 |
| **在线/会话** | `ofPresence` | 在线状态（available/away/dnd/unavailable） |
| | `ofSASLAuthorized` | 已授权会话 |
| | `ofOffline` | 离线消息（对方不在线时暂存） |
| **群聊 MUC** | `ofMucRoom` | 群聊房间 |
| | `ofMucRoomProp` | 房间属性 |
| | `ofMucAffiliation` | 房间成员关系（owner/admin/member/outcast） |
| | `ofMucMember` | 成员 |
| | `ofMucConversationLog` | 群聊会话日志 |
| | `ofMucService` / `ofMucServiceProp` | MUC 服务配置 |
| **群组** | `ofGroup` / `ofGroupProp` / `ofGroupUser` | 用户组 |
| **配置/系统** | `ofProperty` | 系统配置（17 条：认证 provider、端口、安全策略等） |
| | `ofVersion` | 数据库 schema 版本 |
| | `ofID` | ID 序列（roster/group 等自增） |
| | `ofExtComponentConf` | 外部组件 |
| | `ofRemoteServerConf` | S2S 远程服务器 |
| **审计** | `ofSecurityAuditLog` | 安全审计日志（谁何时做了什么） |
| **发布订阅** | `ofPubSubNode` 等 6 张表 | PubSub（XEP-0060 发布订阅） |

### 4.3 常用查询 SQL（速查）

```sql
-- ① 在线会话（在线状态在 Openfire 内存，不在 ofPresence 表）
curl -u "admin:<ADMIN_PWD>" http://localhost:19090/plugins/restapi/v1/sessions
-- 注：ofPresence 存的是「离线 presence」（字段 username/offlinepresence/offlinedate），不是在线用户

-- ② 用户列表
SELECT username, name, email, creationdate FROM ofUser ORDER BY username;

-- ③ 某用户的好友（roster）
SELECT jid, nick, sub FROM ofRoster WHERE username = 'yuzhouxiang';

-- ④ 离线消息积压
SELECT count(*) FROM ofOffline;

-- ⑤ 群聊房间列表
SELECT name, subject, creationdate FROM ofMucRoom;

-- ⑥ 最近安全审计（谁做了什么）
SELECT * FROM ofSecurityAuditLog ORDER BY logid DESC LIMIT 20;

-- ⑦ 系统配置（认证方式等关键配置）
SELECT name, propvalue FROM ofProperty
WHERE name LIKE 'provider%' OR name LIKE 'xmpp.%' OR name LIKE 'security%';

-- ⑧ 各表数据量总览（判断哪些表在增长）
SELECT relname, n_live_tup FROM pg_stat_user_tables ORDER BY n_live_tup DESC;
```

### 4.4 日志查看

```bash
# 实时日志（认证/错误/会话）
docker logs -f collab-openfire

# 认证失败（排障关键）
docker logs collab-openfire --since 1h | grep -i "SASL\|not-authorized"

# 会话空闲关闭（BOSH 假死排查）
docker logs collab-openfire | grep "Closing idle session"

# 错误日志文件（容器内）
docker exec collab-openfire sh -c "tail -50 /opt/openfire/logs/error.log"
```

### 4.5 REST API 查询（路线 B 装插件后）

```bash
# 用户列表 / 查询 / 在线会话
curl -u "admin:<ADMIN_PWD>" http://localhost:19090/plugins/restapi/v1/users
curl -u "admin:<ADMIN_PWD>" http://localhost:19090/plugins/restapi/v1/users/{username}
curl -u "admin:<ADMIN_PWD>" http://localhost:19090/plugins/restapi/v1/sessions
```

### 4.6 建议：做成一个「查询脚本」

为方便后台查询，可把常用查询封装成一个脚本（`scripts/openfire-admin.sh`）：

```bash
#!/usr/bin/env bash
# 用法：./openfire-admin.sh <命令> [参数]
# 命令：users | online | roster <用户> | offline | rooms | audit | props
PSQL="docker exec collab-openfire-db psql -U openfire -d openfire"
case "$1" in
  users)   $PSQL -c "SELECT username, name, email FROM ofUser ORDER BY username;" ;;
  online)  $PSQL -c "SELECT username, presence FROM ofPresence WHERE presence != 'unavailable';" ;;
  roster)  $PSQL -c "SELECT jid, nick, sub FROM ofRoster WHERE username='$2';" ;;
  offline) $PSQL -c "SELECT count(*) FROM ofOffline;" ;;
  rooms)   $PSQL -c "SELECT name, subject FROM ofMucRoom;" ;;
  audit)   $PSQL -c "SELECT * FROM ofSecurityAuditLog ORDER BY logid DESC LIMIT 20;" ;;
  props)   $PSQL -c "SELECT name, propvalue FROM ofProperty WHERE name LIKE 'provider%' OR name LIKE 'xmpp.%';" ;;
  *) echo "用法: $0 {users|online|roster|offline|rooms|audit|props}" ;;
esac
```

## 六、告警规则汇总

| 级别 | 触发条件 | 通知 |
|---|---|---|
| P0 紧急 | IM 登录探针连续 2 次失败 / Openfire 容器 down / postgres 不可达 | 立即钉钉+邮件 |
| P1 重要 | 在线用户 5min 突降 >50% / SASL 失败率 >10% / 内存 >85% / 同步失败持续 | 5min 内通知 |
| P2 提醒 | 堆 >85% / 磁盘 >80% / 慢查询 / 离线消息积压 | 聚合通知 |
