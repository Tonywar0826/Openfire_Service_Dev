# Openfire 最终架构与部署计划（路线 B 定案）

> 版本：2026-09-19 · 状态：**定案，待执行**
> 定案依据：PRD 约束 1「所有外部组件一律通过 REST API 调用，禁止直接读写外部组件数据库」；野火 IM 已整体替换为 Openfire。
> 安全红线：所有密码 / 密钥 / 连接串 [REDACTED]。

---

## 一、最终架构（路线 B）

### 1.1 组件职责（9 容器，不变）

| 组件 | 职责 | 说明 |
|---|---|---|
| web / backend | 业务主系统 | 账号主数据、权限 ACL、IM 凭证签发 |
| postgres | `collaboration`（业务）+ `openfire`（IM）两库 | Openfire 状态库 |
| redis | 缓存 + `im_pwd:<user>` 明文密码缓存 | TTL 24h |
| rabbitmq | 异步事件（通知/公告/归档） | — |
| minio | 文件对象 | 附件归档 |
| **openfire** | XMPP/IM 引擎 | 单聊/群聊/presence/roster/Jingle 信令 |
| coturn | STUN/TURN 媒体中继 | 音视频媒体不走 Openfire |
| onlyoffice | 文档协同（full profile） | 默认不启 |

### 1.2 账号同步（核心变化：直连 DB → REST API）

```
平台后端 (FastAPI)
   │ 建号 / 改密 / 禁用 / 删除 / 重置
   ▼
Openfire REST API 插件 (/plugins/restapi/v1)
   ├─ POST /users               → ofUser（encryptedPassword，Blowfish 可逆）
   ├─ PUT  /users/{username}    → 更新密码/姓名/邮箱
   ├─ POST /users/{username}/roster  → ofRoster（sub=both，全员通讯录）
   └─ DELETE /users/{username}  → 停用影子账号
   （后端不再 asyncpg 直连 Openfire DB ✅ 符合 PRD 约束 1）
```

### 1.3 客户端认证流（不变）

```
平台登录(本地/未来 Keycloak) → 签发平台 JWT
        │ 登录时明文密码写 Redis im_pwd:<username>（TTL 24h）
        ▼
前端 GET /api/v1/im/credentials（JWT）→ {jid, domain, http_bind_path, password}
        ▼
converse.js BOSH(/http-bind/) SASL → Openfire JDBC 认证（ofUser.encryptedPassword）
```

### 1.4 密码存储变化（顺带的安全提升）

| 项 | 现状（路线 A） | 路线 B |
|---|---|---|
| ofUser 密码 | `plainPassword` 明文 | `encryptedPassword`（Blowfish 可逆，Openfire 标准） |
| 后端碰 Openfire DB | asyncpg 直连写表 | **完全不碰**，走 REST API |

### 1.5 数据归属

- 用户/组织/权限/文档元数据 → 平台 postgres（主数据）
- 消息/群聊/roster → Openfire 库（平台只存会话元数据与引用）
- IM 明文密码 → Redis（TTL 24h）+ Openfire encryptedPassword（服务端持有，前端不落盘）

## 四、关键验证点（P2 必须实测，不可假设）

1. **REST API 创建用户的密码落点**：POST /users 后查 `ofUser`，确认是 `encryptedPassword` 而非 `plainPassword`。这是路线 B 安全收益的前提。
2. **roster 端点能力**：`POST /users/{username}/roster` payload `{jid, nickname, subscriptionType}`，确认 `subscriptionType=3` 能建立双向订阅（sub=both），实现「全员通讯录」不退化。
3. **REST API 认证**：确认 secret key（`Authorization: <secret>`）与 basic auth（admin）两种方式，选 secret key 避免 admin 弱口令暴露。

## 七、监控与排障（Openfire 作为 IM 服务端的可观测性）

### 7.1 监控体系总览（分层 + 双栈）

**分层**：L1 基础设施 → L2 应用进程(JVM) → L3 协议/会话(XMPP) → L4 业务/依赖，自下而上定位问题。

**双栈**（沿用 PRD 选型）：
- 指标栈：**Prometheus + Grafana + Alertmanager**（实时阈值告警）
- 日志栈：**结构化日志 → Elasticsearch + Kibana**（事后检索定位）

### 7.2 监控项目清单（具体指标 + 采集方式 + 告警阈值）

| 分类 | 具体指标 | 采集方式 | 告警阈值（建议） |
|---|---|---|---|
| **L1 基础设施** | 容器 CPU/内存/磁盘 I/O/网络 | cadvisor + node_exporter | 磁盘 >80% |
| | 主机磁盘（尤其 WAL 归档 /backups、Openfire logs 增长） | node_exporter | >80% P2 |
| **L2 JVM/应用** | 堆内存 used/max、GC 次数/耗时、线程数、死锁 | Openfire 启用 JMX + jmx_exporter | 堆 >85% P2 |
| | DB 连接池使用率 | JMX | >90% P1 |
| **L3 协议/会话** | 在线用户数 | `ofSession`(status=online) / JMX SessionManager | 5min 突降 >50% P1 |
| | c2s 连接数 / BOSH 会话数 / WebSocket 会话数 | JMX / 管理台 Session Summary | 异常波动 P2 |
| | 空闲会话数（`Closing idle session` 日志计数） | 日志采集 | 激增 P2 |
| | **SASL 认证成功率/失败率 + 失败原因分布** | 日志 `grep SASLAuthentication` / 探针 | 失败率 >10%/5min P1 |
| **L4 消息/业务** | 消息吞吐（msg/min）、MUC 消息量 | JMX / Monitoring 插件 | 归零 P2 |
| | 消息归档量增长 | `ofMessageArchive` 行数 | 异常激增 P2 |
| | **影子账号同步成功率**（后端→REST API） | 后端日志 `Openfire 同步` | 失败持续 P1 |
| **L5 数据库** | Openfire 慢查询、连接池 | postgres_exporter | 慢查 >1s P2 |
| | 表大小增长（ofMessageArchive/ofMucRoom/ofPresence） | 定时 SQL | 逼近磁盘上限 P2 |
| **L6 依赖健康** | postgres/redis/rabbitmq/minio 健康 | 已有 healthcheck + 各自 exporter | 非 healthy P0 |
| | 后端 → Openfire REST API 可达性 | 探针 GET /users | 不可达 P0 |
| **L7 日志/审计** | error.log 异常堆栈 | fluent-bit 采集 | ERROR 关键字 P2 |
| | `not-authorized` 频发（暴力破解信号） | 日志统计 | 单账号 5min>10 次 P1 |
| **L8 端到端探针** | IM 链路健康（登录→发消息→登出） | BOSH 探针脚本 | 连续 2 次失败 P0 |

### 7.3 实施方法（采集器落地）

1. **容器/主机**：cadvisor + node_exporter → Prometheus（docker compose 各加一个 exporter 服务，`networks: collab-net`）。
2. **Openfire JMX**：`bin/openfire.vmoptions` 追加 `-Dcom.sun.management.jmxremote.port=9999 -Dcom.sun.management.jmxremote.authenticate=false -Dcom.sun.management.jmxremote.ssl=false`，挂 jmx_exporter agent 抓取（具体 MBean 名以 `org.jivesoftware.openfire:*` 实际输出为准）。
3. **数据库**：postgres_exporter 抓 `collaboration` 与 `openfire` 两库；表增长用 cron 定时 `SELECT count(*) FROM ofMessageArchive` 推 pushgateway。
4. **中间件**：redis_exporter、rabbitmq 自带 Prometheus 插件。
5. **自定义 IM 探针**（关键，复用现有脚本）：cron 定时跑 `scripts/test-bosh-login.py`（登录→发消息→登出），成功/失败/延迟写入 Prometheus pushgateway，产出 `im_login_success`/`im_login_latency_ms` 指标。这是唯一覆盖「平台→Openfire→客户端」全链路的黑盒探针。
6. **日志采集**：fluent-bit 挂载 Openfire `/opt/openfire/logs/*.log` + 后端 JSON 日志 → ES → Kibana；关键模式（`SASLAuthentication` 失败、`IllegalStateException`、`Closing idle session`）配告警。
7. **告警**：Alertmanager 规则按 7.2 阈值，通知渠道钉钉/邮件/IM 系统消息（复用通知中心）。

### 7.4 排障手册（分层定位法）

**排障顺序**（自下而上，先排除最外层）：连接层 → 认证层 → 会话层 → 消息层 → 媒体层。

**关键诊断命令（实战验证）**：

| 排查点 | 命令 | 判读 |
|---|---|---|
| 区分「Openfire 端 vs 前端」 | `docker logs collab-openfire --since 30m \| grep -iE "SASL\|IllegalState\|Exception\|closed\|disconnect"` | 无输出 = Openfire 端干净，是前端 converse 问题 |
| SASL 认证失败 | `grep -A5 SASLAuthentication` | 看 `not-authorized`(密码/账号错) / `not-found`(未同步) / `isInitialized=false`(WS 通道 bug) |
| BOSH 会话假死 | `grep "Closing idle session"` | 空闲超时关闭，`xmpp.httpbind.client.idle` 默认 30s |
| WebSocket SASL bug | `grep IllegalStateException.*SaslServer` | 改用 BOSH 通道 |
| MUC 进不了群 | 抓 converse `getReservedNick` disco 查询 | 新建房间返回 item-not-found → 显式传昵称 join |
| Jingle 收不到来电 | 抓 IQ `to` 目标 | 必须 full jid（带 /resource），bare jid 被静默丢弃 |
| 认证大小写 | 查 `ofUser.username` | DefaultAuthProvider 会 trim().toLowerCase() 精确查库，须存小写 |
| 账号同步失败 | 查 `ofUser` 有无记录 + `curl /api/v1/im/credentials` | 区分「没同步」vs「同步了但密码错」 |

**常见故障速查表**：

| 症状 | 根因 | 诊断 | 修复 |
|---|---|---|---|
| 停在「Log in」 | BOSH 会话假死/坏会话恢复 | 见上 BOSH 假死 | keepalive=false + 断线重登 |
| 停在「Log in」 | WS 通道 SASL 状态机 bug | `isInitialized=false` | 只用 BOSH |
| 建房者不在群里 | `getReservedNick()` 遇 item-not-found throw | disco 返回 404 | `room.join(昵称)` 显式传参 |
| 收不到音视频来电 | IQ 发到 bare jid | 抓包看 to | 发 full jid |
| 密码对仍 not-authorized | ofUser 用户名大写/带空格 | 查 ofUser.username | 统一 lower() |
| 新用户无法登录 IM | 影子账号未同步 | ofUser 无记录 | 查同步日志/补 sync |

> 排障优先看日志，不要一上来怀疑 Openfire 本身——绝大多数「IM 连不上」最终定位在前端 converse 生命周期或账号同步，而非 Openfire 服务端。
