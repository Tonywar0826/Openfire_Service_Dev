# Openfire 对接测试方法

> 版本：2026-09-19 · 配套文档：《Openfire 对接设计与架构（含 API 详细清单）》
> 读者：Openfire IM 测试/部署负责人
> 说明：本文给出完整测试策略与 35 个测试用例，全程用 curl 命令 + 登录脚本，不需要写代码。

---

## 一、测试策略（四层）

```
L1 环境连通  → L2 接口功能  → L3 IM 登录(协议)  → L4 端到端
（环境起没起）  （接口对不对）   （账号能不能登）    （整条链路通没通）
```

**测试工具**：
- curl（接口测试）
- `test-bosh-login.py`（IM 登录测试）

**测试顺序**：L1 → L2 → L3 → L4 → L5（隔离性），逐层通过再进下一层。

## 四、验收标准

**对接成功的判定**（全部满足才算过）：

1. L1 环境连通：测试环境 REST API 返回 200。
2. L2 接口功能：T3/T4/T5 全部用例预期通过（正常+异常+边界）。
3. L3 登录：T6-01 新账号能真正 BOSH 登录（`<success/>`）。
4. L4 端到端：T7-01 建号→登录→发消息全链路走通。
5. L5 隔离：测试全程正式环境零影响。

**测试报告**：填完 §三 所有用例的「实际结果」列，即构成完整测试报告。

## 五、常见坑（测试时注意）

1. **REST API 插件没装** → 请求返回 302 跳到登录页，不是 404。先确认插件加载（T1-03）。
2. **username 大小写/空格** → 接口能建，但 IM 登录会 `not-authorized`。统一小写无空格。
3. **同步失败 ≠ 平台失败** → Openfire 同步只告警不阻塞，别因为 IM 同步失败误判平台建号失败。
4. **改密后要重启会话** → 已登录的老会话可能仍有效，测试改密登录用全新连接。
